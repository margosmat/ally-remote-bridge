# Hardware acceptance procedure

Use an actual ASUS ROG Xbox Ally X RC73XA, Windows 11 x64, a PS5, and current official PS Remote Play. These are manual release gates, not claimed completed tests. Preserve exact application, driver, Windows, and Sony version details with results.

1. **Driver audit first.** Review the exact INF/catalog/SYS payload, source revision, signer and hashes. On a clean Windows test system, snapshot trusted root stores for CurrentUser and LocalMachine, install with the bridge installer, and compare stores afterward. Verify no certificate was added and test signing/code-integrity settings remain unchanged. Confirm rollback, reboot indication, and a normal nonadministrator session.
2. **Device lifecycle.** Run `AllyRemoteBridge.exe --verify-device`. Confirm one USB DS4 with Sony VID/PID appears, receives a neutral state, and disappears. Repeat after a failed attachment. Start a second instance and verify no duplicate appears. Record any ABI, access, or timeout failure.
3. **Sony decision gate.** Start a normal bridge session, sign in through Sony only, connect to PS5, and verify console control. If Sony rejects the DS4, stop release work here. Do not patch Sony, bypass integrity checks, or downgrade it to claim success.
4. **Buttons and analog input.** Exercise every mapping, diagonals, stick extremes/dead zones, full trigger travel, and simultaneous inputs. Check default and configured chords. Verify an isolated View tap sends Share on release and a consumed chord does not leak Share, Square, Triangle, or Options. Press the prefix before its action button.
5. **Touch.** Use a game that responds to touchpad clicks and swipes. Verify two contacts, lifting either finger first, contact cancellation, leaving overlay bounds, and toggling off during contact. A surface touch must not generate a click. Check Windows/Sony touch outside the overlay and after hiding it.
6. **Motion.** Check diagnostics for actual Windows sensor readings. Calibrate gyro while still. In a motion-enabled game verify positive and negative rotations on X/Y/Z, stationary bias, acceleration and gravity in multiple orientations, latency, and filtering. Save the hardware-specific signed axis permutation only after measurement. If Windows exposes no gyro, capture hardware metadata/report descriptors and implement a verified Bosch adapter before claiming motion support.
7. **Focus and rumble.** Hold buttons while switching to another app. Confirm neutral DS4 state and stopped motors; no touch overlay remains. Enable optional rumble and test feedback. Disable it and document unavailability if Sony or ASUS does not support forwarding.
8. **Failure matrix.** Test Sony normal close, crash, update restart within/outside the grace interval; controller unplug/reconnect and mode change; suspend/resume while holding buttons/touch; Windows logout; bridge termination during attachment and active input. Run `--cleanup`. Confirm only the bridge-owned device is removed while another USB/IP device remains unchanged. Include a nonresponsive-driver case and document safe recovery if cleanup fails.
9. **Other games and internet.** After bridge exit, play an Xbox/Steam title and verify normal physical controller behavior. Test a Remote Play session away from home with Sony's normal network configuration.
10. **Installation and UI.** On clean and already-configured systems, check settings scaling on the 7-inch display, every save/validation path, tray lifetime, offscreen geometry, controller selection, missing DLL/driver, certificate rejection, and emergency stop. Uninstall; verify app files/settings removal and retention of shared USB/IP components. Check alternate-admin-account installation/uninstallation.
11. **Performance.** Measure bridge-only input-to-report latency and total-system CPU during a representative session, alongside Remote Play smoothness. Targets are <5 ms and <2% CPU. Verify there is no sensor activity after session end. Record sample sizes and method rather than extrapolating from a nominal 4 ms polling period.

Record outcomes and evidence in `tests/HardwareTests/acceptance.json`. Change a check to PASS only after running it; explain any unavailable optional rumble. A release needs all mandatory checks passed and all outstanding implementation items resolved.
